Memory Agent model
Which AI does the background memory work after each reply. Leave blank to use your normal AI. A cheap, fast AI works great here and saves money.
Look up memories for each message
Off by default, and the only part of this extension that runs before your reply instead of after it. Everything else picks memories for a message that hasn't been written yet — this one actually reads your message and searches for what it needs, then staples the hits onto the memory sheet in their own clearly-labelled block. It is read-only: it can look, never write. Skipped for short or emote-only messages, and a swipe or a re-roll reuses the same result for free. It costs you waiting time — see below.
Give this one the fastest small AI you have — it is on the waiting path, so it gets a hard deadline of 8s. Miss it and your reply is sent without the looked-up block (nothing breaks, you just don't get the extra memories). Miss it three times in a row and it switches itself off for the session and says so. Your background memory model is usually far too slow for this — that is why this is a separate setting.
Context & budget
How many recent messages your main AI sees while writing. 0 = off (it sees the whole chat, the normal way). With a number set, older history is trimmed and the memory sheet stands in for it — cheaper and more focused. Trimming only kicks in once the first memory sheet exists.
The newest N messages are never mined for facts — you might still swipe or edit them. The Memory Agent only sees them as clearly-labeled tentative context for planning. 4 is the default.
Every N settled messages are distilled into ONE "Story so far" sentence. Smaller = a more detailed story spine but more background LLM calls. 10 is the default.
The Memory Agent staples on a few EXTRA memories connected to the scene's facts. Instead of always the top-ranked ones, it wanders the memory graph at random — restaurant → Luigi's → first date — surfacing a different connected chain each time. This sets how many to collect. 0 turns it off.
On by default. The Reflect pass compares near-duplicate memories and is asked to rule on each pair, checking both against the recent story — one side wins (the other is kept but deprioritized), the two are merged (the folded-in one is kept, deprioritized, never erased), or they honestly coexist. A pair ruled "coexist" stops being offered until one of the two values actually changes, and then it comes back.
The scan itself is free, but the pairs cost prompt space and the Reflect model spends reads on them. 2 is the default; raise it in a long-settled chat.
On by default. Facts tagged with a who-knows list are hidden unless someone in the current scene (the main pair or a PRESENT-listed NPC) is on it, so secrets stay secret. Name matching is alias-aware — "Trish" and "Trish Mitchells" count as the same character. Turn OFF to let every character see every fact (secrets will leak) — useful if facts seem to go missing in a shared database.
Memory Agent — Extra Instructions
Appended to the background Memory Agent's task each run — e.g. genre-specific things to track. The built-in rulebook itself is fixed (cache-stable) and is not edited here.
Catch-up import (existing chats)
Got a long chat from before you turned this on? This reads back through the unprocessed backlog in chunks — one AI call per chunk of messages, resumable if you cancel — and rebuilds the memory sheet at the end. Don't chat while it runs.
Bigger chunks = fewer, cheaper calls but coarser notes. 8 is a good default.
Memory Agent prompt
The FULL system prompt the background extraction agent runs on — it covers only the fact-extraction and NEED-selection pass; the beat and sheet-head passes use fixed built-in prompts. It picks the memories for the NEXT reply and, since the omission-recovery rules were added, also looks BACKWARD: it is shown every memory the last sheet actually carried, plus the VALUES of stored facts about whoever that reply named which the sheet did NOT carry — so a fact the storyteller hedged on or contradicted can be recognised and re-selected instead of guessed at from key names. A memory recovered that way is marked as such and stays injected for the next few turns, not just one. Leave blank or Reset to use the built-in default — a saved copy from an older version keeps running as-is and quietly loses whatever the newer default added. This is separate from the Memory tab's "extra instructions", which are still appended on top of whatever prompt is used here.
Reflect Agent prompt
The FULL system prompt for the periodic Reflect maintenance pass. It is no longer read-only, and no longer memory-only: it is handed the RAW recent chat messages as evidence and its FIRST job is to hunt for stored memories the story contradicts. On top of the summaries and observations it writes declaratively, it can then repair one stored memory at a time (fix a value, fold a duplicate into its survivor, demote noise) and rule on contradicting pairs — every repair gated behind reading the full record first, and capped per pass. Nothing in that path deletes: every demotion keeps the memory and only deprioritizes it. The story evidence is the largest block in the pass and is re-sent each round, so a Reflect pass now costs noticeably more tokens than it used to. Leave blank or Reset to use the built-in default — a saved copy from an older version keeps running as-is and quietly loses whatever the newer default added.

Debug Log
While this is on, every agent call records its full system prompt, the task block it was given, the model’s raw reply, and each tool call with its arguments and its result — the context a memory write was based on. This is the only thing that writes verbose entries. When off it costs nothing: nothing is captured and no text is built.
RAM only: never saved to the chat file or the character card. Switching it off stops the capture but keeps it — what you already recorded stays visible in the log below and stays downloadable. Only a page reload or a chat switch discards it, so download the test run before you do either.
The switch itself is a saved setting and survives both: it stays on across a reload and across a chat switch, so recording resumes on the next chat even though the previous chat’s capture is gone.
The test-run file contains raw roleplay text. Always, whether or not recording was on: fact values and notes, the story spine (a readable plot synopsis), scene cards, the memory sheet, reflection observations, health.events (raw provider error bodies) and lastSentPrompt — the character card, the system prompt and the last N chat messages verbatim, exactly as SillyTavern sent them for the last generation, up to 2 MB. On a recording-off export lastSentPrompt is the single largest piece of raw chat text in the file.
With recording on it additionally holds the agents’ full prompts, the model’s full replies, and every tool call’s arguments and results. Read it before you share it.
